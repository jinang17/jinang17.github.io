## What is DNS (Domain Name System)

It is like a phonebook of the internet that maps the human readable URL to server's IP address like google.com to 142.250.183.46.

## Why do we need DNS?

The Internet works on the simple principle of communication between clients and servers. Let's say you are a client who wants to access information on Google's server. To communicate with that server, you need its IP address. However, as humans, we typically only remember readable names like 'google.com', not numeric IP addresses. We need a system to resolve our queries and address this issue. This is where DNS comes into play. It acts as a phonebook and helps us communicate with servers by providing their IP addresses. Additionally, DNS manages the constantly changing IP addresses of websites. Below figure represent the typical structure of an URL which consists of different parts : Protocol + FQDN ( subdomain + domain name + top level domain ) + path of the file on the server. DNS help us resolving the FQDN part of it.

- **Domain**: The main website name
- **TLD**: The ending part (.com, .net, etc.)
- **Subdomain**: A smaller section of the main site (like blog.example.com)

Now that we understand what DNS is and why we need it, let's explore how the system actually works behind the scenes.

## Terminology

- **DNS Recursor**: The DNS Recursor is the first server in the chain. It accepts your request, queries other DNS servers on your behalf, and ultimately returns the correct IP address to you.
- **Root Nameserver**: It is a DNS server which tells us that which Top Level Domain (TLD) Server we need to go to.
- **TLD Nameserver**: This DNS server handles specific domain extensions like ".com", ".org", or ".net".
- **Authoritative Nameserver**: This DNS server holds the actual records which maps the IP to our URL.

## Steps for a DNS lookup

1. When you enter a URL, the browser first checks its cache (previous records) OS cache, and the system's Hosts file for the IP. If not found, it starts a DNS lookup by sending a recursive query to the local DNS server (DNS Recursor).
2. The DNS recursor then queries a DNS root nameserver (.).
3. The root server than responds with the IP address of a TLD server that will have the information for its domains.
4. The DNS recursor then queries the appropriate TLD server
5. The TLD server will responds with the IP address of an Authoritative Nameserver which will hold the DNS record of the particular URL.
6. The DNS recursor then queries the appropriate Authoritative Nameserver that holds the DNS record
7. The Authoritative Nameserver respond with the right IP address of the corresponding URL.
8. The DNS recursor than respond that back to us and also cache the record so it may reuse that in future for a quick response.
9. Using this IP we can seamlessly communicate with server across the internet :)

Now that we've walked through the basic DNS lookup process, it's important to understand that these lookups can happen in different ways

## Types of DNS queries

In a recursive query lookup, a DNS server does the recursion and continues querying other DNS servers until it has an IP address to return to the client (often a user's operating system). In an iterative query, each DNS query responds directly to the client with an address for another DNS server to ask, and the client continues querying DNS servers until one of them responds with the correct IP address for the given domain.

## DNS caching

DNS responses are cached at different levels to improve speed. Each DNS record has a TTL (Time To Live), which determines how long it stays valid before a fresh lookup is needed e.g. TTL=300 means 5-minute caching

- If TTL is too low, frequent lookups increase load and slow down responses.
- If TTL is too high, changes to DNS records take longer to update.

Choosing the right TTL balances speed and update efficiency.

## DNS zones

To organize DNS information efficiently, the DNS namespace is divided into manageable logical sections called 'DNS Zones.' Each zone has a 'Zone File' - essentially a text document containing the DNS records for that particular section of the internet. Think of a zone file as a specific chapter in the internet's address book, focusing on a particular domain and its subdomains.

The @ symbol represents the root domain (the main domain itself) and IN (Internet) specifies the record class .

## Common DNS record types

- **1️⃣ SOA (Start of Authority)**: Stores admin details & settings for the domain. (e.g., example.com SOA ns1.example.com.)
- **2️⃣ A (Address Record)**: Maps a domain to an IPv4 address. (e.g., example.com → 192.168.1.1)
- **3️⃣ AAAA (IPv6 Address Record)**: Maps a domain to an IPv6 address. (e.g., example.com → 2001:db8::ff00:42:8329)
- **4️⃣ CNAME (Canonical Name)**: Redirects one domain to another (alias). (e.g., www.example.com → example.com)
- **5️⃣ PTR (Pointer Record)**: Resolves an IP address to a domain (reverse DNS lookup). (e.g., 192.168.1.1 → example.com)

## Popular DNS resolvers

- **1.1.1.1** (Cloudflare DNS): Privacy-focused, does not log IP addresses, low-latency performance.
- **8.8.8.8** (Google DNS): High uptime, robust infrastructure, supports DNSSEC.
- **208.67.222.222** (OpenDNS): Offers content filtering, phishing protection, and parental controls.
- **9.9.9.9** (Quad9): Security-focused, blocks malicious domains using real-time threat intelligence.
